Historial de sesiones y super administrador

  1. Cada ingreso crea un registro en la colección sesiones con usuario, inicio, tiempo logueado y acciones. El contador de la sesión actual corre en vivo.
  2. Las acciones se registran solas: guardar Inicio o Contacto, crear/editar/eliminar áreas, abogados y posts, incluir/excluir, cambiar orden, importar y cargar contenido inicial.
  3. El historial muestra 10 sesiones y luego genera barra de desplazamiento. Toque el ojo de una fila para ver el detalle completo de acciones.
  4. Solo sebagsc2020@gmail.com puede eliminar registros. Los demás usuarios ven un candado: las reglas de Firestore rechazan cualquier borrado o alteración hecho por otra cuenta.
El usuario sebagsc2020@gmail.com debe existir en Firebase Authentication con proveedor Correo/Contraseña. Su rol se verifica por el email del token, no por una variable del navegador.

Por qué el equipo del sitio no aparece en el panel

  1. El index.html trae el contenido escrito en su propio HTML como base. Si Firestore está vacío, el sitio igual se ve completo, pero el panel —que solo lee Firestore— muestra la lista vacía.
  2. Solución definitiva: abra Diagnóstico → Importar desde el sitio publicado. El panel lee el index online y escribe ese contenido en las colecciones.
  3. Si el diagnóstico marca permiso denegado, pegue las reglas de abajo en Firestore. Si marca otro proyecto, el index publicado apunta a una base distinta.
  4. Alternativa rápida: use Cargar contenido inicial para escribir todo el contenido de Zarza & Asociados.

Teléfono y WhatsApp por abogado

  1. Abra Equipo → editar (icono lápiz). Complete Teléfono directo tal como quiere que se lea, por ejemplo +54 11 4372-8901.
  2. En WhatsApp del profesional cargue solo dígitos: país + área + número, por ejemplo 5491143728901. Vacío = usa el WhatsApp general del estudio.
  3. La vista previa del editor muestra los botones exactos que verá el visitante. Al guardar se publican al instante y la acción queda registrada.

Reglas de seguridad de Firestore

Incluyen la protección del historial: nadie puede borrarlo ni alterarlo salvo el super administrador.

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Contenido del sitio: lectura pública, escritura solo autenticado (admin)
    match /sitio/{documento} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /areas/{documento} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /equipo/{documento} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /blog/{documento} {
      allow read: if true;
      allow write: if request.auth != null;
    }

    // Historial de sesiones: registro inalterable.
    // Solo el dueño puede agregar acciones; solo el super admin puede borrar.
    match /sesiones/{documento} {
      allow read: if request.auth != null;
      allow create: if request.auth != null
                    && request.resource.data.uid == request.auth.uid
                    && request.resource.data.email == request.auth.token.email;
      allow update: if request.auth != null
                    && resource.data.uid == request.auth.uid
                    && request.resource.data.uid == resource.data.uid
                    && request.resource.data.email == resource.data.email
                    && request.resource.data.inicioMs == resource.data.inicioMs
                    && request.resource.data.acciones.size() >= resource.data.acciones.size()
                    && request.resource.data.totalAcciones >= resource.data.totalAcciones;
      allow delete: if request.auth != null
                    && request.auth.token.email == 'sebagsc2020@gmail.com';
    }

    // Cualquier otra colección permanece bloqueada
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
