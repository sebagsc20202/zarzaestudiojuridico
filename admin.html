Puesta en marcha (una sola vez)

  1. En la consola de Firebase del proyecto zarzaasociados: abra Authentication → Sign-in method y habilite Correo electrónico/Contraseña. Luego, en Users → Add user, cree el email y la contraseña del administrador (los mismos que usa para ingresar aquí).
  2. Abra Firestore Database → Crear base de datos (modo producción, región southamerica-east1 sugerida). En la pestaña Reglas, pegue las reglas de abajo y publique.
  3. Pulse “Cargar contenido inicial” aquí abajo: siembra todas las secciones con el contenido actual de Zarza & Asociados (6 áreas, 4 abogados, 6 posts, portada y contacto).
  4. En su index.html público, pegue el script conector provisto junto a este panel, justo antes de </body>. Ese script renombra el estudio y conecta las 5 secciones a Firestore en vivo.
  5. Publique ambos archivos en el mismo hosting (Firebase Hosting, Netlify, etc.). El panel también funciona abriéndolo como archivo local.
Las reglas permiten lectura pública (el sitio la necesita) y escritura solo con sesión iniciada; el resto de las colecciones permanece bloqueado. Sin ellas, el panel no podrá guardar.

Reglas de seguridad de Firestore

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Contenido del sitio: lectura pública, escritura solo autenticado (admin)
    match /sitio/{documento} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /areas/{documento} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /equipo/{documento} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /blog/{documento} {
      allow read: if true;
      allow write: if request.auth != null;
    }

    // Cualquier otra colección permanece bloqueada
    match /{document=**} {
      allow read, write: if false;
    }
  }
}

Contenido inicial

Escribe en Firestore el contenido completo del sitio ya renombrado a Zarza & Asociados. Puede ejecutarlo las veces que necesite.

Esto sobrescribe los documentos con los identificadores iniciales (áreas, abogados, posts, portada y contacto). Sus documentos nuevos con otros IDs no se tocan.

Cómo se refleja en el sitio

  1. Interruptores (incluido/excluido): ocultan o muestran cada área, abogado, post o dato al instante, sin borrar nada.
  2. Orden: número menor aparece primero. En Blog, los 3 primeros activos forman la portada de publicaciones.
  3. Eliminar borra el documento en forma definitiva (se pide confirmación). Si una colección queda sin documentos, el sitio muestra su contenido base de respaldo.
  4. Los cambios se sincronizan en vivo en cualquier pestaña abierta del sitio público.
